DATABASE REQUIREMENTS
════════════════════════════════════════════════════════════════════════════

The system needs the following tables in your database:

1. CUSTOMERS TABLE
   Structure needed:
     ├─ id (INT, PRIMARY KEY)
     ├─ name (VARCHAR)
     ├─ phone (VARCHAR)
     ├─ city_id (INT)
     ├─ franchise_id (INT)
     └─ Other customer fields

   Used by: Customer search API
   Query: SELECT * FROM customers WHERE phone = ?

2. PRODUCTS TABLE
   Structure needed:
     ├─ id (INT, PRIMARY KEY)
     ├─ name (VARCHAR)
     ├─ city_id (INT) - for filtering
     ├─ price (DECIMAL)
     ├─ is_frozen (BOOLEAN)
     ├─ is_packaging_required (BOOLEAN)
     └─ order_types (VARCHAR) - daily, weekend, alternate

   Used by: Product API
   Query: SELECT * FROM products WHERE city_id = ? AND customer_visible = true

3. ROUTE_SHEET_DETAILS TABLE
   Structure needed:
     ├─ id (INT, PRIMARY KEY)
     ├─ customer_id (INT)
     ├─ delivery_id (INT)
     ├─ delivery_date (DATE) - UPDATED AUTOMATICALLY
     └─ Other route sheet fields

   Used by: Route sheet date update
   Automatic Update: delivery_date = TODAY (if generated as TOMORROW)

4. ORDER_DETAIL TABLE
   Structure needed:
     ├─ id (INT, PRIMARY KEY)
     ├─ customer_id (INT)
     ├─ start_date (DATE) - UPDATED AUTOMATICALLY
     ├─ status (VARCHAR) - 'Y' for active
     └─ Other order fields

   Used by: Order date update
   Automatic Update: start_date = TODAY (if generated as TOMORROW)

5. SALES_RECORDS TABLE
   Structure needed:
     ├─ id (INT, PRIMARY KEY)
     ├─ route_sheet_id (INT)
     ├─ product_id (INT)
     ├─ quantity (INT)
     ├─ sold_date (DATE)
     └─ Other sales fields

   Used by: Sales record insertion
   Automatic Insert: New sales records with transaction safety

SECURITY NOTES
════════════════════════════════════════════════════════════════════════════

⚠️  IMPORTANT SECURITY REMINDERS:

1. DO NOT commit credentials to version control
   - .gitignore the file or externalize credentials
   - Use environment variables for production

2. Use a dedicated database user (not root)
   - Give minimum required permissions
   - Example: SELECT, INSERT, UPDATE on specific tables only

3. Protect the database password
   - Use strong passwords
   - Rotate credentials periodically
   - Store securely (environment variables, config server)

4. Production Setup (Recommended):
   - Use Spring's application.properties with environment variables:
     spring.datasource.url=jdbc:mysql://${DB_HOST}:${DB_PORT}/${DB_NAME}
     spring.datasource.username=${DB_USER}
     spring.datasource.password=${DB_PASS}
   
   - Set environment variables in your deployment:
     export DB_HOST=your-production-host
     export DB_USER=your-db-user
     export DB_PASS=your-db-password

DEBUGGING CONNECTION ISSUES
════════════════════════════════════════════════════════════════════════════

Issue: "com.mysql.cj.jdbc.exceptions.CommunicationsException: 
         Communications link failure"

Solution:
  1. Check if MySQL server is running
  2. Verify host and port are correct
  3. Check firewall allows connection to port 3306
  4. Verify network connectivity to database server

Issue: "Access denied for user 'username'@'host'"

Solution:
  1. Double-check username spelling
  2. Double-check password spelling
  3. Verify user has permission on the database
  4. Reset password if forgotten

Issue: "Unknown database 'beejapuri_QA'"

Solution:
  1. Verify database name spelling
  2. Verify database exists: SHOW DATABASES;
  3. Create database if needed: CREATE DATABASE beejapuri_QA;

Issue: "Column 'X' doesn't exist in table 'Y'"

Solution:
  1. Verify table structure matches expected schema
  2. Alter table to add missing columns
  3. Check if column name is different (case sensitivity)
